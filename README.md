A subscription-based **WhatsApp × Telegram automation bot** — payments via **Paystack**, data in
**Neon PostgreSQL** (Prisma). It shares the same database as the website, so commands and sessions
stay in sync automatically:

- 📜 **Command registry from the website** — the admin edits commands in `/admin/commands` and the
  bot re-imports them **automatically within ~15 seconds** (no restart).
- 📱 **Sessions managed from the website/admin** — pause-free design: **Unlink = logout**,
  **Delete = wipes the session folder + DB row**; the admin "Active" list reflects the bot's real
  `./database/sessions/` folders.
- 🔑 **Pairing keyword `MZAZIBOT`** — the fixed keyword users send to request a WhatsApp pairing
  code (the 8-char code itself is generated by WhatsApp via the custom [Baileys fork](https://github.com/mzazi89/baileys)).

## Quick Setup

### 1. Install Dependencies

```bash
# Clean install is important after replacing an older upload
rm -rf node_modules
npm install
```

This build does not install `sharp`. The bot's Baileys version declares an
older optional sharp peer, while newer sharp releases require a native binary
that can fail on Pterodactyl panels. Removing that optional dependency keeps
pairing, WhatsApp sessions, Telegram commands, and payments from crashing at
startup. The included `.npmrc` also prevents npm from automatically
reinstalling Baileys' optional sharp peer.

### 2. Configure Environment

Copy `.env.example` to `.env` and fill in your values:

```bash
cp .env.example .env
nano .env
```

Required variables:
- `TELEGRAM_BOT_TOKEN` — from [@BotFather](https://t.me/botfather)
- `DATABASE_URL` — Neon PostgreSQL connection string (with `?sslmode=require`)
- `DIRECT_URL` — Same as `DATABASE_URL` (required by Prisma for Neon)
- `PAYSTACK_SECRET_KEY` — from [Paystack Dashboard](https://dashboard.paystack.com) → Settings → API Keys
- `PAYSTACK_PUBLIC_KEY` — same location
- `WEBHOOK_PORT` — port for the webhook server (default `3000`)
- `WEBHOOK_URL` — your public URL (e.g., `https://yourdomain.com`) — set this in Paystack dashboard

### 3. Set Up Database

```bash
npm run db:generate   # Generate Prisma client
npm run db:push       # Push schema to Neon
```

### 4. Configure Paystack Webhook

In [Paystack Dashboard](https://dashboard.paystack.com) → Settings → API Keys & Webhooks:
- Set **Webhook URL** to: `https://your-domain.com/webhook/paystack`

### 5. Start the Bot

```bash
npm start
```

### WhatsApp Pairing and Payment Commands

These commands can be run from a private chat with an already connected bot, so
the user does not need to open Telegram:

| Command | Description |
|---|---|
| `.pair [number]` | Generate a WhatsApp pairing code |
| `.connect [number]` | Alias for `.pair` |
| `MZAZIBOT [number]` | Fixed pairing/access keyword |
| `.plans` | Show the same subscription plans used by Telegram |
| `.pay PLAN_5` | Generate a Paystack payment link |
| `.verify [reference]` | Verify a Paystack payment |

`MZAZIBOT` is a fixed command keyword. The actual eight-character pairing code
must be generated by WhatsApp for every request; replacing it with a constant
would make WhatsApp reject the link.

## Architecture

```
index.js              ← Telegram bot (main entry) — MODIFIED
whatsapp.js           ← WhatsApp connection (Baileys) — MODIFIED (session mgmt, auto-reconnect)
case.js               ← WhatsApp command handler
settings.js           ← Config — MODIFIED (added Paystack, DB, plans)
server.js             ← Express webhook server — NEW
lib/
  prismaClient.js     ← Prisma singleton — NEW
  subscription.js     ← Subscription logic — NEW
  payment.js          ← Paystack integration — NEW
  admin.js            ← Admin panel functions — NEW
  cron.js             ← Hourly expiry jobs — NEW
  database.js         ← JSON DB (preserved) — UNCHANGED
  chatLogger.js       ← Chat logger (preserved) — UNCHANGED
helper/               ← All helpers — UNCHANGED
prisma/
  schema.prisma       ← Neon DB schema — NEW
database/             ← Session files — UNCHANGED
```

**Session files** (`database/sessions/`) are untouched — WhatsApp auth files remain exactly as before.
Only subscription, payment, and user data moved to Neon PostgreSQL.

## Payment Flow

```
User selects plan
       ↓
Bot generates Paystack payment link (via API)
       ↓
User clicks "Pay Now" → completes payment on Paystack
       ↓
Paystack sends webhook → server.js verifies signature
       ↓
Subscription upgraded immediately
       ↓
Bot notifies user ✅
```

If webhook doesn't fire, user can also click **"I've Paid — Verify"** or run `/verify [reference]`.

## Free Plan Behavior

- Each Telegram account can pair **only 1** WhatsApp number
- Attempting a second pair shows the upgrade prompt instead of generating a code
- No existing device is removed when the free limit is reached

## Expiry Behavior

- Runs every hour via `node-cron`
- Expired users are downgraded to Free automatically
- Extra devices beyond 1 are removed (keeping the most recent)
- User is notified via Telegram message
